# Apex AI - Comprehensive Documentation

## 1. System Architecture Overview
Apex AI is a locally hosted, highly modular algorithmic trading framework split into two primary components:
- **FastAPI Backend (Python):** Handles the database, AI agents, execution logic, WebSocket streams, and heavy mathematical computations.
- **Next.js Frontend (TypeScript/React):** Provides a visual control center with dynamic dashboards, charts, and interactive simulators.

### Core Philosophy
The system does not rely on a single monolithic strategy. It utilizes a **Mixture of Experts (MoE)** architecture, where specialized autonomous agents analyze different data streams (e.g., Sentiment, Risk, Market) and a central `CoordinatorAgent` makes the final decision.

## 2. The Agent Swarm
All agents are located in `app/agents/`.

### 2.1 Coordinator Agent (`coordinator.py`)
- **Role:** The brain of the operation.
- **Function:** Calls the Market Analyst, Risk, Sentiment, and Portfolio agents. It compiles their results and asks the underlying LLM (e.g., GPT-4o) to determine a final "GO" or "NO-GO" signal for a specific asset.

### 2.2 Market Analyst Agent (`market_analyst.py`)
- **Role:** Technical Analysis.
- **Function:** Computes indicators (RSI, MACD, Bollinger Bands, ATR, SuperTrend, etc.) from live OHLCV data. Generates a bias (Bullish/Bearish/Neutral).

### 2.3 Risk Agent (`risk_agent.py`)
- **Role:** Capital Preservation.
- **Function:** Enforces the Kelly Criterion. If a trade is deemed too risky or violates maximum drawdown constraints, this agent has veto power to block the execution.

### 2.4 Sentiment & News Agent (`sentiment_agent.py` & `news_agent.py`)
- **Role:** Market Psychology.
- **Function:** Fetches the global Fear & Greed index and parses live news from the CryptoPanic API. It determines if the macro-environment supports a breakout or warns of a flash crash.

### 2.5 Evolution Agent (`evolution_agent.py`)
- **Role:** Continuous Learning (Phase 6).
- **Function:** A post-mortem engine. When a trade closes, this agent analyzes the entry, exit, and PnL, using an LLM to extract a "Lesson Learned." This is saved to the `trade_lessons` database to prevent repeating mistakes.

### 2.6 Macro Agent (`macro_agent.py`)
- **Role:** "What-If" Simulation (Phase 7).
- **Function:** Projects the impact of macroeconomic variables (DXY, FED Interest Rates) onto the crypto market. Generates "Flash Reports" explaining market mechanics.

### 2.7 Predictor Agent (`predictor_agent.py`)
- **Role:** Machine Learning Forecasting.
- **Function:** Trains a `RandomForestClassifier` on historical candles. It engineers features like returns and volatility to predict whether the next candle will be bullish or bearish.

## 3. The Execution Layer

### 3.1 Smart Order Routing (SOR) (`app/core/sor_engine.py`)
The system connects to Binance, KuCoin, and Bitget via the `ccxt` library (asynchronous). When a trade is approved, the SOR engine scans the order books of all connected exchanges and routes the order to the one offering the best price (lowest slippage).

### 3.2 Arbitrage Scanner
Using the SOR engine, the system constantly monitors the bid/ask spread across exchanges. If a spread is detected that covers the trading fees (e.g., Buy on KuCoin, Sell on Binance), it flags a risk-free arbitrage opportunity.

### 3.3 Execution Agent (`execution_agent.py`)
Takes the route provided by the SOR engine and executes a LIVE market order. Immediately follows up by placing an OCO (One-Cancels-the-Other) order on the exchange, simultaneously setting the Stop-Loss (SL) and Take-Profit (TP).

## 4. Risk & Portfolio Management

### 4.1 PyPortfolioOpt Integration (`app/core/sentinel.py`)
Instead of fixed position sizing, Apex AI uses Modern Portfolio Theory (MPT). 
- It calculates the covariance matrix of all assets.
- It determines the **Max Sharpe Ratio** allocation to ensure the portfolio yields the highest expected return for the lowest mathematical risk.
- **Usage:** Viewable in the "Portfolio" tab on the frontend.

## 5. Database Schema (PostgreSQL)

The system relies on a relational database (`app/db.py`) with the following key tables:
- `paper_trades`: Stores all open and closed trades (both live and simulated).
- `historical_ohlcv`: Acts as a local data warehouse for fast backtesting without hitting rate limits.
- `trade_lessons`: Stores the post-mortem analysis generated by the Evolution Agent.
- `experiment_runs`: Tracks the results of the Strategy Lab.

---

## 6. Security & Architecture Guidelines
1. **Never commit `.env` files.** The `.env` contains your Binance/KuCoin API keys and OpenAI tokens.
2. **Local Priority:** The AI models and logic run entirely on your local machine. No trading algorithms or strategies are exposed to the public internet.
3. **Vercel / Ngrok Proxy:** The frontend deployed on Vercel acts purely as a "dumb terminal". It connects to your local PC via Ngrok websockets. If your PC is off, the trading stops.
